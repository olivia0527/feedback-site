# feedback-site Spec

## Problem Statement

수업이 끝난 뒤 선생님은 학생이 무엇을 이해했는지 확인하고 학생마다 피드백을 주기 어렵다. 학생의 글과 수정 내용을 한곳에서 보기 어렵고, 새 글이나 수정된 글을 놓칠 수 있다. 학생도 자신의 글을 제출하고 선생님의 피드백을 확인한 뒤 수정 글을 다시 제출하는 흐름이 필요하다.

## Solution

학생과 선생님이 역할별 화면에서 같은 수업 기록을 확인하고 이어서 작업할 수 있는 단일 페이지 웹 화면을 만든다.

선생님은 근무하는 학교를 설정하고 학교 코드를 확인·공유한 뒤, 당일 수업 주제와 안내 질문을 입력해 수업을 만든다. 학생은 학교 코드로 해당 수업에 들어가 안내 질문을 보며 배운 내용을 3~5문장으로 제출한다. 선생님은 제출된 글을 읽고 텍스트 피드백을 남긴다. 학생은 피드백과 이전 글을 함께 확인하고 글을 수정해 다시 제출한다. 수정 글은 선생님 화면에 갱신된 글로 표시되며, 선생님은 횟수 제한 없이 다시 피드백할 수 있다.

피드백은 별도의 외부 채널 없이 수업 기록 안에 텍스트로 남기고, 학생 화면에서 이전 글과 함께 보여 준다. (AI 제안)

## User Stories

1. 선생님으로서 근무하는 학교를 설정하고 싶다. 학생이 내가 만든 수업에 들어올 학교를 정할 수 있도록 하기 위해서다.
2. 선생님으로서 학생에게 공유할 학교 코드를 확인하고 싶다. 학생이 해당 학교의 수업에 들어올 수 있도록 하기 위해서다.
3. 학생으로서 학교 코드를 입력해 해당 학교의 수업에 들어가고 싶다. 선생님이 만든 수업을 확인하고 글을 쓸 수 있도록 하기 위해서다.
4. 선생님으로서 당일 수업 주제를 입력해 새 수업을 만들고 싶다. 학생에게 오늘 배운 내용을 작성할 대상을 제공하기 위해서다.
5. 선생님으로서 수업에서 사용할 안내 질문을 입력하고 싶다. 학생이 무엇을 써야 하는지 이해할 수 있도록 하기 위해서다.
6. 학생으로서 현재 수업의 주제와 안내 질문을 보고 싶다. 글을 쓰기 전에 수업의 맥락과 작성 기준을 확인할 수 있도록 하기 위해서다.
7. 학생으로서 안내 질문을 참고해 배운 내용을 3~5문장으로 작성하고 싶다. 수업에서 이해한 내용을 자신의 말로 정리할 수 있도록 하기 위해서다.
8. 학생으로서 작성한 글을 제출하고 싶다. 선생님이 내 글을 읽고 피드백할 수 있도록 하기 위해서다.
9. 선생님으로서 제출된 학생 글을 한곳에서 보고 싶다. 새 글을 놓치지 않고 학생의 이해 내용을 확인할 수 있도록 하기 위해서다.
10. 선생님으로서 학생의 글을 읽고 텍스트 피드백을 남기고 싶다. 학생에게 이해한 점과 보완할 점을 전달할 수 있도록 하기 위해서다.
11. 학생으로서 선생님이 남긴 피드백을 확인하고 싶다. 내 글에 대한 다음 학습 방향을 알 수 있도록 하기 위해서다.
12. 학생으로서 피드백을 확인할 때 이전에 제출한 글도 함께 보고 싶다. 어떤 글을 바탕으로 피드백을 받았는지 알 수 있도록 하기 위해서다.
13. 학생으로서 피드백을 반영해 글을 수정하고 다시 제출하고 싶다. 선생님에게 개선된 이해 내용을 보여 줄 수 있도록 하기 위해서다.
14. 선생님으로서 학생이 다시 제출한 수정 글을 확인하고 싶다. 학생의 수정 내용을 놓치지 않고 이어서 피드백할 수 있도록 하기 위해서다.
15. 선생님으로서 수정 제출에 대해 다시 피드백하고 싶다. 학생이 수정할 때마다 학습을 이어 갈 수 있도록 하기 위해서다.
16. 선생님으로서 피드백을 여러 번 남길 수 있어야 한다. 피드백 횟수에 막히지 않고 학생의 수정 과정에 응답할 수 있도록 하기 위해서다.
17. 학생으로서 역할에 맞는 화면만 사용하고 싶다. 학생 기능과 선생님 기능을 혼동하지 않고 작업할 수 있도록 하기 위해서다.
18. 선생님으로서 역할에 맞는 화면에서 학교, 수업, 학생 글, 피드백을 관리하고 싶다. 선생님에게 필요한 작업을 한곳에서 수행할 수 있도록 하기 위해서다.
19. 학생으로서 브라우저를 새로고침해도 제출 글과 받은 피드백을 다시 보고 싶다. 수업 기록이 브라우저 안에 보존되도록 하기 위해서다.
20. 선생님으로서 브라우저를 새로고침해도 학교, 수업, 학생 글, 피드백을 다시 보고 싶다. 저장된 수업 기록을 이어서 확인할 수 있도록 하기 위해서다.

## Implementation Decisions

- 기능 이름(feature-slug)은 `feedback-site`로 한다.
- 화면은 `index.html` 하나에 모두 담는다. PRD에서 나눈 학생 화면과 선생님 화면은 별도 페이지로 이동하지 않고 이 파일 안에서 역할 전환으로 바꿔 보인다.
- 학생 화면과 선생님 화면은 역할별 기능이 구분되도록 구성한다.
- 선생님 화면에서는 학교 설정, 학교 코드 공유, 수업 생성, 학생 글 확인, 피드백 작성, 수정 글 확인을 제공한다.
- 학생 화면에서는 학교 코드로 수업 입장, 수업 주제와 안내 질문 확인, 3~5문장 글 작성·제출, 피드백과 이전 글 확인, 글 수정·재제출을 제공한다.
- 피드백은 수업 기록에 텍스트로 저장하고 학생 화면에서 피드백 대상이 된 이전 글과 함께 표시한다. 별도 메시지 서비스나 알림 채널은 사용하지 않는다. (AI 제안)
- 모든 데이터는 브라우저의 `localStorage`에 저장한다. 데이터베이스, 서버 API, 외부 인증은 사용하지 않는다.
- 저장 대상은 학교 설정, 학교 코드, 수업의 주제와 안내 질문, 학생 제출 글의 현재 내용과 이전 글, 각 제출 글에 연결된 선생님 피드백이다.
- 학생이 수정 글을 제출하면 기존 글을 삭제하지 않고 이전 글로 보존하며, 선생님 화면에는 가장 최근 수정 글이 표시된다.
- 피드백 작성 횟수에는 제한을 두지 않는다. 학생의 각 제출 글에 대해 선생님이 다시 피드백할 수 있다.
- 학교 이름과 수업 주제는 특정 값으로 고정하지 않는다. 가상의 가람중학교나 「전기와 자기」를 기본값으로 고정하지 않는다.
- 이메일 알림, 학생끼리 다른 학생의 글을 보는 기능, 학생 회원가입·로그인, 데이터베이스 연동은 구현하지 않는다.
- 서버나 데이터베이스가 없으므로 저장된 데이터는 현재 브라우저의 `localStorage` 범위에서만 유지된다. 여러 브라우저 사이의 동기화는 제공하지 않는다. (AI 제안)

## Testing Decisions

- 테스트 도구와 자동화 테스트는 사용하지 않는다.
- 사용자가 브라우저에서 직접 눈으로 확인할 수 있도록, 하나의 `index.html`을 열어 학생 화면과 선생님 화면을 전환하며 핵심 흐름을 확인한다.
- 확인할 외부 동작은 다음과 같다.
  - 선생님이 학교를 설정하고 학교 코드가 보이는지
  - 선생님이 수업 주제와 안내 질문을 입력해 수업을 만들 수 있는지
  - 학생이 학교 코드로 수업 화면에 들어가 주제와 질문을 볼 수 있는지
  - 학생이 글을 제출한 뒤 선생님 화면에 새 글로 나타나는지
  - 선생님이 피드백을 남긴 뒤 학생 화면에 피드백과 이전 글이 함께 나타나는지
  - 학생이 글을 수정해 다시 제출한 뒤 선생님 화면에 수정 글로 나타나는지
  - 선생님이 수정 글에 횟수 제한 없이 다시 피드백할 수 있는지
  - 브라우저를 새로고침한 뒤 `localStorage`의 기록이 유지되는지
- 구현 내부 함수나 저장 방식 자체가 아니라 사용자가 화면에서 관찰하는 결과를 기준으로 확인한다.

## Out of Scope

- 이메일 알림
- 학생끼리 서로의 글을 보는 기능
- 학교를 가상의 가람중학교로 고정하는 기능
- 수업 주제를 「전기와 자기」로 고정하는 기능
- 피드백 횟수 제한
- 데이터베이스 저장
- 서버 API와 외부 인증
- 학생 회원가입·로그인
- 브라우저 간 데이터 동기화
- PRD에 없는 추가 기능

## Further Notes

- 이 Spec은 `exercises/PRD.md`의 문제, 대상, 핵심 장면, 만들지 않을 것을 기준으로 작성했다.
- 저장소에 용어집(`GLOSSARY.md`)과 관련 ADR이 없어 PRD의 용어인 학교, 학교 코드, 수업, 학생, 선생님, 글, 수정 글, 피드백을 그대로 사용했다.
- 피드백 전달 방법만 PRD에서 `[미정]`으로 남아 있어, 가장 단순한 수업 기록 내 텍스트 표시 방식으로 정했다. 해당 결정에는 `(AI 제안)`을 표시했다.
